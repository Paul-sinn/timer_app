## A. 이미 커밋됨 — 다음 빌드에 자동 포함

코드가 들어가 있고 빌드·테스트를 통과한 상태다. 따로 할 일 없이 다음 빌드를 올리면 포함된다.

### A1. 🔴 동기화 데이터 잘림 버그 수정 *(확정 버그)*

`ce3f4b0` · `SyncService.swift`

기록이 **1000개를 넘는 순간부터** 서버가 응답을 조용히 잘라 보낸다(PostgREST `max-rows` 설정값 = 1000, 확인 완료). 잘린 행을 앱이 "서버에 없다"고 판단해 **앱을 켤 때마다 같은 데이터를 다시 업로드**하고, 완전 동기화에 영영 도달하지 못한다.

- 500행씩 나눠 받기 + 정렬 tiebreaker(`id`)로 페이지 경계에서 행이 새거나 겹치지 않게
- 업로드도 500행 청크로 분할
- 응답에 필요한 컬럼만 요청

**하루 3세션 기준 약 1년이면 도달한다.** 헤비 유저는 더 빨리. 이게 다음 업데이트의 가장 큰 이유다.

### A2. 🟠 동기화 실패 처리

`ce3f4b0` · `SyncRetryPolicy.swift` · `SyncErrorMapper.swift`

기존에는 모든 실패를 `try?`로 삼켜서 무슨 일이 일어나는지 아무도 몰랐다.

- 일시적 실패(네트워크·5xx·429)만 지수 백오프 + **지터**로 재시도
- 지터가 핵심: 없으면 서버 복구 순간 모든 기기가 동시에 재시도해 다시 넘어뜨린다
- 인증 실패·쓰기 쿼터 초과·정체불명 에러는 재시도하지 않음
- 연속 실패 시 차단기가 백그라운드 전송을 멈춤

### A3. 🟠 원격 킬스위치 (클라이언트)

`66c0ff9` · `RemoteConfig.swift`

서버에서 `app_config.sync_enabled`를 `false`로 바꾸면 원격 동기화가 멈춘다. **이 코드가 들어간 버전부터 작동한다.**

서버 테이블은 이미 라이브에 있다. 즉 **지금 심사 중인 1.0에는 킬스위치가 없다** — 1.0이 출시되면 그 버전 유저들은 서버에서 제어할 수 없다.

### A4. ⚪ 검수용 환경변수 릴리스 제외

`bfdfd67` · `RootView.swift`

`START_TAB` 훅이 `#if DEBUG` 밖에 있었다. 실질 위험은 없었지만(외부에서 환경변수 주입 불가) 문서와 코드가 어긋나 있었다.

## B. 화면 연결

### B1. ✅ 동기화 상태를 사용자에게 보여주기 — **완료**

`MyPageView`가 `isSyncing`만 보고 아이콘을 **항상 `checkmark.icloud`로 고정**해서 그리고 있었다. 동기화가 며칠째 실패해도 화면에는 정상으로 보였다.

`MyPageView.syncState`가 우선순위대로 판정한다:

| 상태 | 아이콘 | 색 | 추가 안내 |
|---|---|---|---|
| 진행 중 | `arrow.triangle.2.circlepath.icloud` | `eggAccent` | — |
| 서버 일시중지(킬스위치) | `icloud.slash` | `textSecondary` | "이 기기에 저장됨, 자동 재개" |
| 실패 | `exclamationmark.icloud` | `danger` | 실패 종류별 문구 |
| 정상 | `checkmark.icloud` | `eggAccent` | — |

설계 판단 두 가지:
- **일시중지를 실패보다 먼저 판정한다.** 킬스위치가 켜져 있으면 동기화를 아예 시도하지 않아서, 직전에 남은 실패 메시지가 계속 떠 있게 된다. 지금 상태를 말해주는 쪽이 정확하다.
- **일시중지에 경고색(`danger`)을 쓰지 않는다.** 장애가 아니라 의도된 중단이다.

> 새 문자열 3개가 아직 `Localizable.xcstrings`에 없다. 앱이 영어 단일 언어이고 키 자체가
> 영문 문장이라 **런타임 표시는 정상**이다. Xcode에서 빌드하면 자동 추출된다.
> 한국어를 재도입할 때(B2) 확인할 것.

**남은 검증**: 실기기/시뮬레이터에서 눈으로 확인 — 특히 킬스위치를 켠 상태의 카드 모양.

### B2. 🟡 한국어 재도입 (선택)

현재 앱은 영어 단일 언어다(2026-07-28에 통일). 한국어 번역 283개가 `Localizable.ko-orphans-backup.json`에 백업돼 있다. 되살릴지는 제품 판단.

## D. 서버 전용 — 앱 업데이트와 무관

**이미 프로덕션에 적용됨.** 심사 중인 1.0에도 지금 바로 적용되고 있다.

| | 적용일 |
|---|---|
| 권한 최소화 (anon 전권 회수, TRUNCATE 제거) | 08-09 |
| 회원가입 트리거 예외 안전화 | 08-09 |
| 값 범위 제약 + 미래 시각 거부 | 08-09 |
| 유저당 일일 쓰기 쿼터 (5000행) | 08-09 |
| 킬스위치 테이블 `app_config` | 08-09 |

롤백이 필요하면 → [`docs/supabase/ROLLBACK.md`](supabase/ROLLBACK.md)

### D1. ⏸ `delete-account` 엣지 함수 배포 — **심사 끝나고**

CORS 제한·POST 강제·예외 메시지 비노출까지 고쳐뒀지만 **배포하지 않았다.**

계정 삭제는 App Store 심사 필수 요건(5.1.1(v))이다. 심사 중에 배포했다가 깨지면 리젝 사유가 된다. 현재 배포된 버전도 정상 동작한다(CORS가 넓을 뿐, JWT 없이는 호출 불가).

**배포 후 앱에서 계정 삭제를 한 번 눌러 확인할 것.**

### D2. 🟡 부하 테스트

"몇 명까지 버티나"는 아직 **측정한 적이 없다.** 지금까지 한 건 코드를 읽고 문제를 찾은 것이다.

순서: Pro 업그레이드(백업·브랜치) → 가짜 데이터 시딩 스크립트 → k6로 50→1,000명 → 측정값으로 서버 크기 결정

합격 기준: p95 < 1초 / 오류율 < 0.5% / CPU < 70% / 데이터 누락 0
안전 수용량 = 통과한 최대치의 **절반**

급하지 않다. 사람이 몰릴 조짐이 보이면.
